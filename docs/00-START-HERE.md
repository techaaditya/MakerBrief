# Your build sequence

1. Run the application locally and complete the agreement workflow once without API credentials.
2. Run tests. Read domain.mjs and confirm the invariants match the product you want.
3. Prepare a consenting adult's suitable source photo and a permissioned outerwear reference. Record allowed uses in the asset register.
4. Add your API key only to `.env`; configure your own image-host allowlist and enable live mode. Use privately controlled storage URLs that YouCam can retrieve.
5. Run one live transaction. Record actual version, parameters, balance debit, latency, output shape and visual failures. Do not claim success from the mocked adapter tests.
6. Replace fictional options with one maker's real garments and permitted options. Keep references for each revision honest.
7. Implement authenticated buyer/maker collaboration and persistent private asset storage before public live inference.
8. Conduct the small task-based evaluation, resolve failures, record the real product demonstration and assemble the submission.

The central outcome is an agreed commission specification. Images support that outcome. More endpoints are useful only if they settle a real decision.

All guides are design and implementation recommendations; business figures are hypotheses, not demonstrated results. Winning cannot be guaranteed.
