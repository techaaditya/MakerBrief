# Product specification

## Audience and task

Start with one custom clothing maker and remote customers. A buyer wants to know how a garment could look and exactly what the maker has agreed to produce. A maker wants fewer ambiguous requests, a clear quote and a record of approved choices. Those needs should be verified in interviews, not assumed to describe every tailor.

## Core workflow

Buyer selects a real catalog garment, describes preferences, generates a personal visual preview, and submits a brief. Maker reviews production feasibility, marks preview discrepancies, confirms materials and details, and issues a quote. Buyer approves that exact revision and quote. Later changes reopen relevant review.

## Acceptance criteria

A buyer can create and revise a brief. The server rejects unsupported options and stale revisions. Every revision remains available. Quote values are integer minor currency units, with explicit currency and lead time. Buyer approval requires a current quote, a maker confirmation and a resolved detail review. A new quote invalidates old buyer agreement. A specification change invalidates the old quote and approvals. A detail concern revokes current agreement until resolved. The export reproduces current status and history.

## Product limits

The image is a visual reference, not physical fit, measured dimensions or a construction pattern. Fabric, yardage and lead-time promises belong to the maker. No cultural history is generated automatically. Add maker-reviewed attribution where relevant. No photo analysis of sensitive identity is needed.

## Distinctiveness

Personal VTO alone already exists. The proposed contribution is the link from preview discrepancies to a versioned, actionable commission. Demonstrate a meaningful change and the resulting stale approvals, not just an attractive render.
