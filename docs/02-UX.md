# Experience and design direction

Use warm paper, forest ink and restrained olive accents. The central garment image should be prominent, with the production details alongside it. Typography and whitespace should convey a careful atelier rather than a technical dashboard.

The included UI has Buyer studio and Maker desk modes, a visual panel, specification form, quote panel, agreement status and decision history. Live mode is inside an explicit disclosure and requires consent. Demonstration illustrations and fictional catalog data are labeled.

For the final product, replace the role switch with separate authenticated review links. Buyer screens should show one obvious action at each stage. Maker screens should focus on the fields requiring confirmation, discrepancies and quote changes. Move from generic approval to field-level evidence and responsibility as the catalog grows.

Provide clear empty, waiting, failed, unknown and outdated states. Never relabel a submission timeout as a provider rejection; the job may exist. Preserve the buyer's edits when polling, and avoid rebuilding focused forms during background refresh. The starter refreshes the UI while a live job runs, so keep that limitation in mind when refining it.

Test keyboard navigation, visible focus, readable contrast, mobile zoom and screen-reader labels. Announce status changes politely. Keep a text equivalent of every meaningful image observation. Preview quality must be reviewed by a person, not represented as an invented match percentage.

Use real screen captures from the finished product for submission. Illustrations are suitable for setup, but not evidence of a successful API integration.
